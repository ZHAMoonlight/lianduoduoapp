# 练多多产品方向与当前范围

更新日期：2026 年 10 月 25 日。

练多多支持“独立教练与私教工作室的学员经营”：先服务已经有学员、需要安排训练与管理课包的教练。独立教练可以一个人完成建档、收款登记、课程时间地点、履约反馈与续课跟进，无需门店或团队。工作室则继续使用机构模式分工协作。个人主页、流量获客和营销转化不在本轮实现内，不能与“支持教练本人独立使用”混为一谈。

软件已经实现真实本地管理后台、共享组织账号和原生微信小程序，不再停留在固定身份示例空间。当前先满足教练本人无店使用的明确需求；面向更多教练或工作室的持续使用、价格和经营增量仍待验证。商业假设与软件完成度分别判断，不因缺少客户而把已完成能力写成未开发，也不因代码可运行便宣称提高续费率。

## 定位与取舍

基础约课、会员经营、AI 助手和连锁管理已有多种竞品覆盖。“加 AI”“提供预警”或价格落在某个区间，不能单独证明差异化；原调研中“功能空白”与普遍支付上限的结论已在 [竞品判断修订](RESEARCH_REVIEW.md) 中纠正。

| 路线 | 当前选择 | 再评估依据 |
| --- | --- | --- |
| 独立教练的既有学员经营 | 当前默认使用方式；无店、本人管理的本地闭环已实现 | 教练能否持续使用，是否减少实际工作量及愿意付费 |
| 工作室学员跟进与续课 | 兼容机构分工与可运行本地闭环 | 老板是否愿指定负责人、持续使用并实际付费 |
| 个人主页、营销与获客 | 尚未实现；与独立使用模式分开评估 | 独立经营主体、自有学员和可重复触达渠道 |
| 少儿体育与家长成长服务 | 候选分支 | 有机构愿长期组织反馈，且家长使用与购买决策有明确关联 |
| 加盟跨店清分 | 保留基础内部记账 | 真实合同、赠课/退款/对账样例、专人和付费试点承诺 |
| 通用场馆管理、门禁及硬件 | 不列入当前主线 | 首期工作流与付费验证之后另行决定 |

受雇教练不会自动取得学员资料的所有权或跨店经营权。访问范围来自组织授权、本人授课及明确的学员/跟进分配。若实际客户资源集中在其他客群，应根据真实接触、数据和付款承诺调整切入点。

## 两种工作空间

本地独立空间没有一年服务到期锁，仍须处于 active 状态；机构服务到期限制及课包自身有效期照常校验。后台空库首次开通默认独立教练，保留姓名、账号、密码；小程序先微信验证，未绑定时仅填姓名及可选空间名、科目即可创建本人的独立空间，不设置密码。独立空间真正没有 Store 记录，不生成虚拟门店；学员、课包和课程的 `storeId` 为空，由本人直接管理。课程保留自由填写的实际上课地点，支持一对一或小班。

独立 owner 在内部使用 `hq + 本人 coachId`，界面显示独立教练，没有平台授权，也没有门店、团队、审核或跨店入口。唯一执教档案的 `selfManaged` 表示本人自主管理自己的训练服务，不代表通过机构审查、证书核验或外部认证；本人排课不受机构证书到期门槛阻挡，课包科目、有效期和时间冲突等规则仍校验。

机构模式明确选择后才创建首家门店，继续使用平台、总部、店长和受雇教练的授权关系；旧租户 mode 未填写时仍按机构处理。两种模式不是同一套界面中用虚拟店伪装，不能通过请求参数随意更改模式。

## 已实现的协作入口

| 入口 / 角色 | 当前可执行工作 |
| --- | --- |
| 独立教练 | 本人管理全部学员、课包收款、课程时间地点、代约签到消课、反馈和续课跟进；学员自助账号可选 |
| 平台管理员（机构模式） | 创建和维护组织、开通组织管理员、查看平台范围审计；不能在请求中任意替换组织身份 |
| 组织总部 | 建立门店、教练、学员、员工账号；排课履约、订单课包、学员跟进、内部跨店记账与审计 |
| 门店店长 | 管理本店档案、课包订单、排课与履约、学员跟进；可开通本店教练及学员账号 |
| 教练 | 本人课表、授课签到消课、课堂反馈；处理明确分配给自己的学员跟进 |
| 学员 / 获授权的监护人账号 | 查看绑定学员、课表和课包，预约取消、查看流水与反馈 |

后台为 Vite + React 网页，保留现有账号密码初始化、登录与账号管理。小程序为原生 Page/WXML/WXSS，只有微信登录入口，含独立开通和本人经营页；无需先进入 PC 后台建店。二者调用同一 Node + SQLite 服务。后台在尚无账密用户时按所选模式首次开通；小程序的未绑定微信可在空库或已有业务库中创建自己的私有 solo，不覆盖旧组织，没有预置示例课程或学员。不同员工共享获授权组织数据，只能切换自己已有的授权上下文。

微信已绑定账号直接进入原有授权；未绑定取得 5 分钟一次性开通凭证，仅留 App 内存，填写姓名后创建自己的无店空间与本人 hq+coach 授权。新微信用户不设置密码，也不能使用密码接口登录。尚未绑定的旧机构账号不自动迁移，不按姓名或手机关联；当前小程序没有账密或绑定入口。后台开通员工/学员账号的既有能力保留，但不等于已经把该账号绑定微信。若先有微信新用户，后台仍能首次创建独立的账密账号和自己的新工作空间，保留微信原数据且仅获自己空间 hq；两种账号不自动合并，也不能接管对方空间。已有账密用户后不再允许首次 setup。

账号可绑定多个学员，绑定由管理者明确指定；本版没有自动亲属关系核验、监护申请和撤销工作流。该授权能力不等同于已完成未成年人身份核验。

## 从建档到续费的当前闭环

1. 独立教练直接新增学员，默认由本人负责；机构先完善门店和教练资质，再为学员分配负责教练。
2. 核对经营者已实际收款的线下凭证，登记课包和独立订单。续费新建课包及订单，不覆盖旧卡历史。
3. 填写课程时间和实际地点，由教练代约；需要且已有明确微信绑定与学员授权时，可由学员自行预约与取消；未绑定旧账号本轮不自动接入。预约冻结课时，上课签到后确认完成才消课，生成逐笔权益流水。
4. 本人或店长按现有事实生成去重跟进，也可人工创建；独立教练默认自己执行，机构可分配负责教练。
5. 记录联系内容、设置下次日期、标记已联系，并提交明确处理结果。
6. 选择“已续费”结案时，必须关联同一学员在跟进创建后登记的有效已付款订单，由服务端再次核验。

独立教练是自己空间的经营者，可看自己的收款与账本。机构受雇教练只能修改自己分配任务的日期/状态、追加联系和结案，不能创建、批量生成或重新分配；其续费候选仅含订单 ID、日期和课包名，不暴露经营财务数组。

## 当前规则与结果口径

跟进状态为 `open → contacted → closed`，记录联系不会隐式等同成交。结案结果为恢复训练、已核验续费、暂缓、明确不续费或其他，并保留文字说明。恢复训练是经营者或员工登记的结果类型；实际是否到课应另查履约记录，不把文字标记当自动行为证据。

目前提供固定规则：

- 可用余额不超过 3 课时。
- 活跃课包将在 14 天内到期。
- 存在真实完成记录、距最近完成至少 30 天，且没有未来有效预约的长期未到课学员。

同学员同原因的未结束任务去重；生成时默认分配给学员负责教练。独立模式由本人负责；机构未设置负责教练时由门店处理。阈值当前不可配置，尚无暂停标记或拒绝联系名单自动抑制规则；经营者应先复核事实再联系，不将生成任务称为流失预测。

已核验续费表示满足订单关联条件，不证明该订单由跟进促成。原始收付款真实性来自经营者人工核验的凭证，并非微信支付渠道自动回调。当前未实现到期群体续费率、对照归因、经营增量分析或 AI 预测。

## 权益、异常与资金边界

| 业务 | 当前明确规则 |
| --- | --- |
| 课时 | 可约 = 剩余 − 冻结；预约只加冻结；取消释放；完成同时减少剩余与冻结 |
| 学员取消 | 必须严格早于开课前 60 分钟；到达截止点后交由本人教练或门店处理 |
| 迟取消 / 旷课 | 本人教练或授权员工填写原因，按允许时间登记；本版释放冻结，不扣剩余 |
| 停课 | 仅未开课且没有签到/完成的课程可取消，释放相关预约冻结 |
| 退款登记 | 仅无消课、无冻结的整包全额退款；先由经营者实际退款，再登记凭证 |
| 跨店记账（仅机构） | 跨店完成课程生成单据，保留金额快照；确认不触发转账或自动支付 |
| 课后反馈 | 完成课程后记录真实课堂观察与评价，按授权范围展示；不推断伤病或训练效果 |

金额按整数分存储，课时按整数节存储。单场展示价格、课包实收、课时履约价值和内部结算金额是不同口径。界面登记收款净额不是支付渠道对账结果，不标成自动到账收入。

## 当前尚未交付的能力

- 个人主页、营销活动、公开获客与流量分发。
- 授权导入旧系统、来源映射、批量迁移、第三方系统同步。
- 在线微信支付、渠道退款、自动分账、订阅消息和资料文件存储。
- 证书真实性查询、教练资料补传/复核、亲属关系核验。
- 密码找回、员工离职撤权管理界面、完整的消课冲正与部分退款。
- 周期排课、候补、复杂补课、可配置经营规则、AI 草稿或预测、自动群发。
- 真实续费率和经营增量报表、完整加盟月结与外部财务对账。

当前自有约课与权益账可以独立运行，但不能声称已与客户原系统同步。如果并行试点仍以原系统为权威，应明确分工，在人工复核前不要在两套账中重复扣课；导入方案需要另行开发与验收。

## 商业验证与下一步

本次仅本地启动，不部署 Sites，不发布小程序。小程序微信登录及未绑定自建 solo 已实现；真实上游仍需匹配 AppID/AppSecret 和实际微信环境验证。配置统一在 `app/.env`，进程环境优先；保留现有 AppID，AppSecret 只供服务端读取。`config:wechat` 或 dev/build/start 仅白名单生成小程序公开配置，绝不复制 Secret。当前 Secret 尚空，不宣称真实微信授权成功。

下一步用现有本地产品观察独立教练实际使用，并访谈工作室经营负责人，验证名单是否有用、教练是否愿意录入、结果是否便于核对，以及双系统维护与实施成本。3 家试点、两周工作流观察、后续 6–8 周权益周期观察都是实验安排，并非已发生的结果。详见 [试点计划](VALIDATION_PLAN.md)。

尝试由独立经营者或工作室付费，按明确范围和期限报价；价格、免费策略和支持成本尚未确定。内部继续门槛可暂定为 3 家试点至少 2 家持续处理并记录结果、至少 2 家实际付费继续，但不把小样本当市场成功率或效果保证。

工程可用性与商业价值分别验收：本地启动、权限、事务和客户端测试见 [架构](ARCHITECTURE.md)、[验收](ACCEPTANCE.md)；客户证据与后续扩展由真实使用和付款决定。
