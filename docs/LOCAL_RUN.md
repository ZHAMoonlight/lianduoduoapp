# 本地启动与使用

更新至 2026 年 10 月 28 日，Node 异步 mysql2 + MySQL 8.4 管理后台与原生微信小程序。后台保留账号密码，小程序仅微信登录。本次只本地运行，不部署 Sites，不发布小程序。

## 1. 启动开发环境

需要 Node.js 22.13 或以上及 Docker/Compose。先配置 `app/.env` 的 MySQL 连接与密码，在仓库根目录执行：

```sh
cd app
npm ci
npm run db:up
npm run db:init
# 仅首次保留原 SQLite 数据时执行；全新空库跳过。
npm run db:migrate -- --source ./data/lianduoduo.sqlite
npm run dev
```

后台：[http://127.0.0.1:5173](http://127.0.0.1:5173)；API（当前 `.env` 端口）：[http://127.0.0.1:43101/api/setup](http://127.0.0.1:43101/api/setup)。`initialized` 表示是否已完成后台账密开通：false 时仍可首次创建账密账号；即使库中已有微信新用户，也不锁死此入口。true 表示已有账密用户，应使用已有后台账号。该字段不表示数据库是否为空，也不限制新的未绑定微信创建私有独立空间。

后台首次开通默认「独立教练」，姓名、账号、密码必填，空间名称与科目可选。账号 3–64 位，允许英文字母、数字及 `._@-`，密码至少 10 位，没有默认密码或示例业务数据。机构需明确选择「机构门店」，填写组织和首家门店；旧 mode 未填写仍按机构处理。后台现有账密登录与账号管理不变。纯微信用户之后的后台首次开通，会追加独立账密账号及自己的空间，保留原微信数据且仅给自己 hq，不给 platform；不按姓名或手机合并，也不能接管微信空间。真正全空库机构开通仍保持原平台授权逻辑；已有账密用户再 setup 返回 409。

独立模式不建 Store 或虚拟店，自动建本人执教档案，课程时间/地点自由填写，无需团队或机构审核。selfManaged 表示本人自主管理，不代表资质认证。本地 solo 没有一年服务到期锁，仍须 active；机构到期与课包自身有效期保留。

按 Ctrl+C 停止 API/后台；数据库使用 `npm run db:stop`，保留 Docker 命名卷 `lianduoduo_mysql_data`，不要用 `down -v` 重启。MySQL 在 `127.0.0.1:43306`，数据库与业务用户均为 `lianduoduo`。旧 SQLite 文件及 `app/data/backups/` 仅作备份与一次迁移输入，不删除，也不再作为运行时存储。

首次 `db:init` 以管理员建表/触发器，日常 API 使用独立业务用户；不关闭 binlog，也不向业务账号授予 SUPER。连接配置、导入校验和停止方式见 [MYSQL.md](MYSQL.md)。

## 2. 配置与端口

现行 API 选用 43101，避开已被其他应用占用的 3001；地址取自本项目 `.env`。API、后台代理及小程序已有会话连接复验通过。

只读取 `app/.env`，进程环境值优先，`.env.example` 为字段参考。保留现有 AppID，AppSecret 只填服务端，不写入前端。以下仅为字段示例，不代表当前密钥值；MySQL 的两个密码字段需要自行填写，不使用空示例：

```dotenv
HOST=127.0.0.1
API_PORT=43101
WEB_PORT=5173
DB_CLIENT=mysql
MYSQL_HOST=127.0.0.1
MYSQL_PORT=43306
MYSQL_USER=lianduoduo
MYSQL_PASSWORD=
MYSQL_DATABASE=lianduoduo
MYSQL_CONNECTION_LIMIT=10
# 仅 Compose/db:init 使用；日常 API 不使用 root。
MYSQL_ROOT_PASSWORD=
# MYSQL_SCHEMA_USER=root
WECHAT_APP_ID=wx97ef043984618d67
WECHAT_APP_SECRET=
MINIPROGRAM_API_BASE_URL=http://127.0.0.1:43101
MINIPROGRAM_REQUEST_TIMEOUT_MS=15000
```

服务端微信配置已补齐；43101 的 `/api/setup` 返回 200、`wechatConfigured:true`，5173 首页与 `/api/setup` 同源代理均为 200。小程序配置指向 43101，全新重开后恢复已有会话并进入工作台；本轮没有重新执行 wx.login，不将此项称为新 code exchange 验收。既往真实微信登录成功记录保留。修改 AppID/密钥后需重启；不在文档中展示密钥。配置存在与每一次上游登录结果仍应分别检查。

从 `app` 运行：

```sh
npm run config:wechat
```

`dev`、`build`、`start` 也会自动同步。白名单生成 `miniprogram/config.js` 的 API 地址与超时，并更新 `project.config.json` 的 AppID，保留其他设置；Secret、MySQL 密码及管理员凭据不复制前端。需要改小程序地址时修改 `.env` 后同步，不直接把密钥写入项目。

临时改端口：

```sh
npm run dev -- --port 5174 --api-port 3002
```

浏览器走 Vite 同源 `/api` 代理，小程序直连 API。API 改端口时还要同步 `MINIPROGRAM_API_BASE_URL`，避免小程序仍请求旧地址。

## 4. 微信小程序首次使用

1. 微信开发者工具导入仓库 `miniprogram` 目录，不选整个仓库或 app，无需另装 npm 依赖；保留 `.env` 中现有 AppID。
2. 本地工具可使用当前关闭合法域名校验的开发设置；这是本机调试用途。
3. 点击微信登录，`wx.login` 的 code 交给服务端 `POST /api/auth/wechat`。已绑定则进入原有授权。
4. 未绑定时领取 5 分钟开通凭证，只保存在 App 内存；填写姓名与可选空间名/科目，经 `POST /api/auth/wechat/register` 创建自己的 solo，无账号密码，无 Store，无平台权限。凭证过期需重新验证。
5. 新微信可以在已有业务库中创建私有 solo，不能接管旧组织。此前已绑定的旧账号保留原授权；旧机构账号不按姓名或手填手机号合并；后台新建且未被其他账号占用的教练档案可通过下述微信手机号流程领取。本版小程序没有账密或旧账号绑定入口。后台原有账密与旧兼容 API 保留。

小程序只接受服务端标记为微信登录的会话，旧账密缓存不能绕过入口。新微信用户没有可用密码凭据；后台当前没有让该微信新用户直接账密登录的开通流程。

真机的 `127.0.0.1` 指手机自己。需电脑监听可达网卡（例如 HOST=0.0.0.0）、网络互通，将 `.env` 的小程序 API 改为电脑可达地址并重新同步。正式 HTTPS、合法域名与发布权限另行接入，本次不发布。

## 5. 独立教练业务检查

当前小程序独立工作台通过六张一级卡直达「新建学员 / 收款开卡 / 安排课程 / 为学员预约 / 学员跟进 / 收款记录」。从工作台进入的 solo 表单保存成功返回工作台，失败保留输入；收款记录展示当前空间授权可见的全部订单，旧 hub 仍保留最近 5 笔。机构教练、店长和总部仅显示授课与跟进卡，不开放 solo 管理入口。

独立工作台统计使用真实学员数、active、未过期且仍有剩余课时的有效课包数，以及选定日期 scheduled 课次数。课表按时间轨展示，独立 owner 在空态可直接点击「安排一节课程」。2026-10-28 已在微信开发者工具实际检查首屏六卡、六个直达入口及原生返回；没有新增真实业务记录。保存成功返回与失败保留由客户端回归验证。截图见 [新版工作台](/Users/xupeng/aicode/lianduoduo/app/outputs/workbench-redesign/workbench-verified-2026-10-28.png)。

- 添加第一位学员，默认本人负责，不选门店或其他教练。
- 核验真实线下收款后登记课包、科目、课时和有效期。小程序开卡支持选填流水号与上传凭证；业务 API 的开卡/续卡均接受选填流水号和附件，PC 续卡保持流水号选填。当前小程序没有续卡入口。空流水号可多次登记；非空编号去除首尾空白后，同品牌重复仍拒绝。
- 填课程起止时间、实际地点、人数并代约；签到不扣课，完成才消课，查看流水并记录反馈。

- 学员自助为可选，依赖已有微信绑定与明确学员授权；后台建立旧账密账号不等于小程序已绑定。教练可直接代约完成全部闭环。

独立 owner 内部为 hq + 本人 coachId，只有本人空间授权，没有 platform。实体 storeId 为空但仍按租户隔离；上课地点不是门店。机构继续原有门店、资质、学员分配和员工协作路径。

线下开卡/退款登记不发起微信支付；机构跨店确认不转账。个人主页、公开获客和营销转化未实现。历史后台及原生业务 GUI 记录见验收文档，原生旧账密登录记录不证明新微信链路已通过。

### 收款凭证上传

小程序开卡可选择最多 3 份收款凭证，每份不超过 10 MiB（10,485,760 字节），支持 JPG/JPEG、PNG、WebP 图片和 PDF。可拍照、从相册或聊天文件选择；上传失败可重试或移除，不把失败文件作为已保存凭证提交。

文件内容以 BLOB 私有持久化在 MySQL，预览须经业务会话鉴权，不能通过公开静态链接访问。上传和订单提交时校验学员、空间及售卡范围；订单只关联服务端真实附件。本人上传、尚未关联订单的草稿可移除；已关联的历史凭证可按授权预览，不能删除或复用于另一订单。

业务 API 的 card.issue/card.renew 接受选填 receipt 和 receiptAttachmentIds；小程序目前只提供开卡上传界面，PC 续卡仅保留流水号选填。本次未增加小程序续卡或 PC 上传入口，也不代表接入微信支付。退款规则不变：仍须真实退款凭证与原因，且仅允许无消课、无冻结的完整课包全额登记退款。

## 教练账单报表与线下结算

电脑后台新增一级菜单「教练账单」。总部可核对组织各门店，店长仅本门店，教练仅自己的授课和账单；独立教练空间也可使用，无需建立虚拟门店。学生和平台身份不提供此报表入口。

先按授课日期、门店、教练筛选，查看已授课节数、完成人次、消耗课时、消课价值与授课明细，再生成账单。日期使用上海时区的课程开始日，范围两端均包含。只有明确完成的预约计入，取消、缺席、迟取消、仅预约和仅签到不作为教练课酬依据。多人同一课次的授课节数只计一次，人次和消课课时逐笔汇总。

消课价值优先使用真实 consume 账本的整数分金额，不使用课程展示价。历史记录缺账本时可使用课卡单位价值估算并明确标记；缺少可靠金额时显示待核实。报表和预览由服务端在完整授权来源上计算，跨店售卡的分摊尾差不会因门店工作区裁剪而丢失。消课价值是核对依据，未设置课酬规则前不代表教练应付工资。

生成账单须选择一位教练、一个授课门店（独立空间为空）和日期范围，并填写以下一种规则：

- **每节固定课酬**：按不同课次计算，多人课只付一次。仍有预约或签到待处理的课次暂不纳入；同课次已入账后不能重复领取固定课酬。
- **消课金额提成**：按尚未入账的完成预约计算。比例精确到 0.01%，以合计金额四舍五入到分，再分配到明细，保证逐笔合计一致。无可靠金额的明细须先核实。

必须先预览明细和金额，再确认生成待结算账单。服务端保存当时的课次、学员、规则、价值来源与课酬快照，后续更名或其他课卡操作不会重算旧账单。预览内容已变化时会拒绝提交并要求重新核对；已入账预约不会再次入账，重叠范围也不能重复领取课酬。

实际线下支付后，在账单详情中登记「已结算」并填写实际结算日期，转账参考与备注选填。该操作只记录结算事实，不发起资金支付，不修改学员课卡、消课账本或跨店内部清分单。已结算账单保留原始记录，重复相同请求不会重复登记，冲突的支付信息会被拒绝。报表和账单支持 CSV 导出，输出包含 UTF-8 BOM，并对公式开头的文本做转义。

账单保存在 MySQL schema v6 的 coach_bills 表，日常启动自动完成新增表迁移。小程序原有业务保持，本轮账单交互入口在电脑后台。

## 同一教练关联多个门店

已关联微信的教练自动获得目标门店 coach 授权；原有教练、独立空间及学员身份保留。未绑定微信时，在小程序填写目标店团队码与登记手机号加入。刷新小程序会话后，同品牌同一教练有多个门店授权时，「我的」会显示「切换工作门店」；也可从「当前业务身份」选择门店。切换后仅显示该店已授权课表、学员、跟进和课包资格，保留当前店本人授课中服务器已授权的跨店到访学员。课程页的门店名称与地址整行也可点击，直接选择已授权门店并在原页刷新；保留选中日期、清空科目与教练筛选，学员与总部原有门店浏览继续使用本页筛选。

排课按同一 coachId 统一检查所有门店的时间重叠，固定循环课与开放可约时间均生效。账单按实际授课课次的门店统计，历史课程、消课与账单不因增加关联而改归属。资质审核仍由总部或主店管理人员处理。停用的已有授权不会通过重新关联自动恢复，账号归属冲突须先由管理员核对。
